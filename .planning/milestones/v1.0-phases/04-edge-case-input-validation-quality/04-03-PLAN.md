<objective>
Write the orchestrator-judgment half of this phase's detection surface: how a
role/permission guard is recognised inside a route handler regardless of how the
project wraps its error response, and what counts as a detectable required-field or
invalid-format signal — with a test that proves both rules find what they claim,
including against the helper-wrapped guard shape the existing imperative-error pattern
silently misses.

Purpose: D-03 splits permission detection across two tiers. RLS parsing is deterministic
(plan 04-02). In-code role guards have no schema library to parse against, so they stay
orchestrator judgment — and a rubric built only on the existing
`NextResponse.json({error},{status})` regex under-reports real guards in the target repos,
which is the same silent-zero failure mode Phase 3's no-Zod pitfall already cost this
project once.

Output: two new rubric sections in `references/discovery-nextjs.md` and their
anti-drift proof in `scripts/discovery-surfaces.test.mjs`.
</objective>

Add a second section, `## Required-field and format detection`, after it. It states what this
project is entitled to treat as a detectable signal for the three DISC-04 subcategories:

and CUIL check digits, Argentine phone number shapes — are not detected or generated here, and
name `DOM-01` in `.planning/REQUIREMENTS.md`'s v2 section as where that work is tracked, so a
reader does not mistake the omission for an oversight. Close with the same finding-nothing rule:
an undetected format is an undetected format, never a field without a format requirement.
