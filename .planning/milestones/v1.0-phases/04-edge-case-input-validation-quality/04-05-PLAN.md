<objective>
Introduce D-01's second, optional test credential as a real dispatch contract: a boolean
`--secondary` flag on `scripts/api-client.mjs` that makes `readConfig()` resolve
`QA_AGENT_TOKEN_SECONDARY` instead of `QA_AGENT_TOKEN`, two loud refusals so a permission
case can never run as the wrong identity, and a per-case record of which credential was
actually used so D-05's role-delta inference has evidence to compare.

Purpose: DISC-05's permission cases are only executable if the agent can act as a second,
lower-privilege user. Today `readConfig()` resolves exactly one token and `runCase`'s
evidence cannot tell two runs of the same case apart. Without this plan, the permission-case
generation protocol plan 04-06 writes has a `pendiente` branch and no runnable branch at all,
and D-05's "infer the role delta from what the two credentials can do" has nothing to diff.

Output: `useSecondary` on `readConfig()`, the `--secondary` CLI flag, the
`--secondary`/`--storage-state` conflict refusal, `evidence.request.auth.credential` on every
captured case, its rendering in the Markdown report, and the whole contract documented in
`SKILL.md`'s `## Configuration` and `## Case construction`.

**Phase goal (verbatim from ROADMAP.md):** Test cases the agent generates systematically
cover input-validation boundaries and negative/permission edge scenarios, grounded in the
constraints discovered in Phase 3, not just the happy path.
*(ROADMAP's `**Goal:**` line for this phase is not in `As a / I want to / so that`
user-story form; per MVP-mode rules no story is invented here.)*
</objective>
