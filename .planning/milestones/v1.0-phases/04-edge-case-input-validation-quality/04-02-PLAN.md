<objective>
Finish the deterministic SQL-parsing tier this phase needs: allowed-value sets from an
inline `CHECK (col IN (...))` (the invalid-format half of DISC-04 that
`CREATE TYPE ... AS ENUM` cross-referencing never caught), and structured RLS policy
records from `CREATE POLICY` — the net-new discovery surface D-03 requires, currently
counted and discarded by `discover-schema.mjs`'s own design.

Purpose: permission-case generation (DISC-05) has no deterministic input until
`CREATE POLICY` is parsed instead of skipped, and D-11's invalid-format cases have no
grounded value set until an inline `IN (...)` CHECK is recognised. Both belong in the
deterministic script tier, not orchestrator judgment — the `CHECK` versus `WITH CHECK`
ambiguity is exactly what this module exists to resolve.

Output: `parseCheckEnum()` and `extractPolicies()` exported from
`scripts/discover-schema.mjs`, an `allowedValues` field per constraint, a top-level
`policies` array, and the `withCheckSkipped` counter renamed to match what it now means.
</objective>

Add an exported pure function `parseCheckEnum(checkExpr)` to `scripts/discover-schema.mjs`,
placed beside `parseCheckBounds`, with the same doc-comment discipline: state that this
recognises the second, structurally different enum shape real migrations use — an inline
`CHECK (col IN ('a','b'))` — which the existing `CREATE TYPE ... AS ENUM` cross-reference never
sees because that path matches on the column's declared type name, not on its check expression.

Recognise `<identifier> IN ( <single-quoted literal list> )`, case-insensitive on `IN`,
tolerant of newlines and of whitespace around the parentheses and commas, returning the literal
values in declaration order. Return `null` for anything else, including a subquery form whose
parenthesised body contains no single-quoted literals. Keep the regex bounded and
non-backtracking for the same untrusted-input reason `parseCheckBounds` does (threat T-04-03).

`enumMap` lookup that already populates `enumValues`), otherwise `parseCheckEnum(c.check)` when
`c.check` is non-null, otherwise `null`. Keep `enumValues` exactly as it is — `allowedValues` is
the unified field downstream generation reads, and `enumValues` stays the provenance-specific
one, so a reader can still tell a declared enum from an inline CHECK set.
