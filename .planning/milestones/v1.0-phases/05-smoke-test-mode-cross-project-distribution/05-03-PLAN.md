<objective>
Make the written installation instructions sufficient on their own: a teammate copies the
folder, runs one command, sets the variables the skill actually needs, and invokes it — with
every step stated in order, every prerequisite named, and nothing added that the developer
already rejected.

Purpose: PKG-03 is the claim that distribution is "copy it into your skills folder and go".
The only thing standing between that claim and reality is the wording of two documents, so
this plan tightens exactly those two and then proves the steps are mechanically sufficient by
following them verbatim into a clean directory — leaving D-12's real teammate dry run as the
end-of-phase check it was chosen to be.

Output: a numbered, prerequisite-complete `## Installation` procedure and the
`## Configuration` prose it leans on in `SKILL.md`, tightened registration and verification
wording in `references/mcp-setup.md`, and a recorded clean-directory rehearsal of the
documented steps.

**Phase goal (verbatim from ROADMAP.md):** The agent supports a fast post-deploy smoke check
and is packaged so any teammate can install it and run it unmodified against any of the
team's projects.
*(ROADMAP's `**Goal:**` line for this phase is not in `As a / I want to / so that`
user-story form; per MVP-mode rules no story is invented here — see the planner handback
note.)*
</objective>

Rewrite `SKILL.md`'s `## Installation` section as a numbered procedure in the same style
`## UI authentication and session reuse` already uses — sequential steps, concrete command
blocks, and an explicit statement of what is deliberately not done. The steps, in order:

1. Copy or symlink this directory to `~/.claude/skills/qa-agent/`, naming both mechanisms and
   noting that a Windows directory junction is the symlink form this repo's own scripts are
   written to survive — `isMainModule` in `scripts/api-client.mjs` and
   `scripts/test-case-doc.mjs` resolves realpaths precisely so the junction install works.
2. Run `npm install` **inside the copied skill folder**, once. State that this is the copied
   folder and not the project under test, which the current wording leaves to inference. State
   that dependencies are not vendored or pre-bundled and that this manual step is deliberate —
   the copy stays light and this is one command.
3. Set the environment variables `## Configuration` lists, pointing at that section rather
   than duplicating the list, and naming which ones an API-only run actually requires.
4. For a browser run only, register the Playwright MCP server once per machine, deferring to
   `references/mcp-setup.md` for the exact command and the two registration scopes. State
   plainly that an API-only run needs none of this, which the current wording says and which
   must survive.
5. Invoke the skill through its slash command with a base URL and an instruction, in the shape
   `argument-hint` already publishes.

Name the prerequisites the current wording leaves implicit: the Node version `package.json`'s
`engines` field actually requires, read from that file rather than recalled; that the skill is
invoked from a Claude Code session opened on the target project; and that nothing beyond these
steps is needed per project.

Preserve, in intent and in force, the existing claim that nothing is installed into or written
to the project under test besides the `qa-reports/` run artifacts the skill produces at run
time, and that there is no project-specific setup step (PKG-01). That sentence is the whole
basis of the PKG-02 and PKG-03 claims; tightening the section around it must not soften it.

Do not add an install script, a post-install verification checklist, a bootstrap command, or
any new environment variable — all of those were considered and rejected for this phase, and
adding one here would quietly reverse a decision the developer made explicitly.

Then tighten `## Configuration` only where it is genuinely ambiguous for a first-time
installer: make it unambiguous which variables a first API-only run needs versus which are
needed only for a browser run or only for permission cases, and keep the exit-code-only
presence-check rule and the "never read the env file, never print the variable" prohibition
stated exactly as forcefully as they are now. Do not restructure the exit-code table beyond
what plan 05-01 already changed in its code-9 row, and do not move variables between
sections.
