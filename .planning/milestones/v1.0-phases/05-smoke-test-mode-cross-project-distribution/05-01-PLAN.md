<objective>
Prove the whole smoke path on one already-generated document, end to end: a deterministic
selector reduces a validated test-cases document to one `positivo` case per discovered
surface, the reader's CLI exposes that set as machine-readable JSON, and `SKILL.md`'s new
`## Smoke-test protocol` hands exactly that set to the existing Run protocol without adding
a single new execution mechanism.

Purpose: REP-03 stands or falls on one question — can "corré un smoke test" reach a running
subset deterministically, without the orchestrator re-deriving "essential" by eye and without
a second, smaller discovery path? This plan answers it on the thinnest possible path before
the cross-project and packaging plans build out from it.

Output: `selectSmokeCases()` exported from `scripts/test-case-doc.mjs`, a `--smoke` branch on
that module's existing CLI, a golden fixture carrying the three selection edges, and the
`## Smoke-test protocol` section plus smoke trigger phrases in `SKILL.md`.

**Phase goal (verbatim from ROADMAP.md):** The agent supports a fast post-deploy smoke check
and is packaged so any teammate can install it and run it unmodified against any of the
team's projects.

  <action>
Add an exported pure function `selectSmokeCases(parsedDoc)` to `scripts/test-case-doc.mjs`,
placed after `findCase` and before `validateTestCasesDoc`, carrying the same "why, not just
what" doc-comment discipline the rest of the module uses. The comment must name the two
ambiguities this function resolves: that "essential" is defined by a deterministic rule over
the document's own structure rather than by the orchestrator's judgment (D-01), and that a
surface which contributes nothing is a fact the caller has to be able to report rather than a
silent absence.

The rule (D-02): iterate `parsedDoc.surfaces` in document order; for each surface take the
first case whose `tipo` is `positivo`, exactly one per surface. Push it onto `selected` with
the surface's `heading` attached as a `surface` property alongside the case's own parsed
fields. A surface with no such case contributes nothing to `selected` and one entry to
`skipped` carrying that surface's `heading` and a `motivo` string. Never fabricate a case for
an uncovered surface, and never fall through to a `negativo` or `edge` case — that is the
"shape observed, not invented" discipline this project has applied since Phase 1, and here it
means the honest answer to "this surface has no happy path documented" is to say so.

A selected case that carries `pendiente: true` stays selected. Do not look past it for a
runnable alternative: the rule names the first `positivo`, and quietly running a different
case than the rule names would report a surface as smoke-checked on the strength of a case
the rule never chose. Its `pendiente`/`pendienteMotivo` ride through on the returned object so
the existing pending refusal in `## Running generated cases` step 4 can fire unchanged.

Return `{ selected, skipped, counts }` where `counts` carries `surfaces`, `selected`,
`skipped`, `pendientes` and `byEjecucion` (`API` and `UI` keys) — mirroring
`validateTestCasesDoc`'s existing `counts` shape, including 04-04's decision that pendientes
is counted as its own key rather than nested inside `byEjecucion`, so a reader does not have
to re-parse the document to learn how many of the selected cases the run would refuse.

Throw nothing from this function. An empty `parsedDoc.surfaces`, or a document where every
surface lacks a `positivo`, returns an empty `selected` with the surfaces named in `skipped`.
Structural document problems are already `parseTestCasesDoc`'s `TestCaseFormatError` and stay
there — this phase introduces no new failure mode.

validate fallthrough. It resolves `--file` with the existing code-2 checks unchanged, reads
the markdown, calls `parseTestCasesDoc` inside a `try`, calls `selectSmokeCases` on the
result, and writes one line of `JSON.stringify` to stdout with exit 0. A `TestCaseFormatError`
from the parse is caught and reported on stderr with exit 9, exactly as the `--case` branch
already does. Introduce no new exit code: a smoke selection reuses 0/2/9, because D-07's
