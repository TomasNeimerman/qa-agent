<objective>
**As a** developer testing one of our Next.js apps, **I want to** have the QA agent log into the target app as a dedicated test user and then keep using that same session for API checks, **so that** I never have to hand it a second credential or re-authenticate mid-run.

This is the phase's tracer slice: one path wired through every layer this phase touches — environment variables, a real Chromium browser, an accessibility-role-driven login form, a `storageState` artifact on disk, and Phase 1's existing `APIRequestContext` HTTP tier — proving end to end before any Playwright MCP surface is added on top.

Purpose: Phase 2's two hardest, least-documented mechanics are (a) whether a `storageState` file exported from one Playwright context is genuinely consumable by a separate `APIRequestContext` (RESEARCH Pattern 4, Assumption A2), and (b) whether the UI credential can be kept out of the orchestrator's context the way Phase 1 kept `QA_AGENT_TOKEN` out of it (RESEARCH Pitfall 1, locked as D-08). Proving both on this slice, first, means a failure here costs one commit rather than an entire phase of MCP wiring built on a false premise.

Output: a Chromium binary present on the machine, a login-form HTTP fixture, `scripts/ui-login.mjs`, a `--storage-state` flag on `scripts/api-client.mjs`, and an end-to-end test that fails if any link in that chain breaks.

Implements D-03 (fields located by accessibility role/label, never a per-project CSS selector), D-04 (`QA_AGENT_UI_USER`/`QA_AGENT_UI_PASSWORD`, fail loudly when unset), D-07 (export `storageState` and reuse it for API calls in the same run), and D-08 (the login step itself is script-driven so the plaintext password never becomes a tool-call argument).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell environment → `ui-login.mjs` process | `QA_AGENT_UI_PASSWORD` crosses here and must go no further; this is the only process permitted to hold the plaintext value |
| `ui-login.mjs` process → orchestrator (LLM) context | Everything the script prints enters the conversation transcript; a leak here is permanent and unretractable |
| `ui-login.mjs` → storage-state file on disk | A live session credential is materialised as a readable file inside the target project's working tree |
| storage-state file → `api-client.mjs` → target app | Session cookies are replayed against a real localhost or staging environment |
| target app's login page → Chromium | Untrusted page content (markup, labels) drives which controls the script fills |
