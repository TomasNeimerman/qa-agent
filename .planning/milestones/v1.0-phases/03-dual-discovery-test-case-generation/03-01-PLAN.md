<objective>
**As a** developer who wants regression coverage for one of our Next.js + Supabase apps, **I want to** point the QA agent at the project and get back a written list of test cases it derived from the code itself, **so that** I never have to read route handlers and migration files by hand to work out what is worth testing.

*(Story derived from the ROADMAP Phase 3 `**Goal:**` line, which is not itself written in user-story form. No scope was added — "reading the target project's code" and "documented test cases ready for the Phase 1/2 executors" are both taken verbatim from that goal.)*

This is the phase's tracer slice: one path wired through every layer this phase touches — a real target-project source tree on disk, the deterministic SQL-constraint tier, the orchestrator's own reasoning over what it read, the document format contract, and a written `qa-reports/<run-id>-test-cases.md` — proving the whole chain before route/form/Server-Action discovery (plan 03-02) or the execution handoff (plan 03-03) is built on top of it.

Purpose: RESEARCH.md's Open Question 1 asks the planner to decide explicitly where the deterministic/judgment line sits. **This plan ratifies RESEARCH's recommendation with one addition.** Deterministic: SQL migration constraint extraction (`discover-schema.mjs`), because the `CHECK (` versus `WITH CHECK (` ambiguity is empirical proof a freehand grep-and-reason pass gets it wrong. Deterministic: *reading back* the generated document (`test-case-doc.mjs`), because at execution-request time the alternative is the orchestrator eyeballing a grep result to pick a case — the exact anti-pattern this project already refuses for HTTP verdicts, and the mechanism RESEARCH Pitfall 5 shows collides on `case-1` versus `case-12`. Orchestrator judgment, per RESEARCH: finding route/form files (Glob/Grep/Read), labeling a case positivo/negativo/edge, and **authoring** the document with the Write tool. `test-case-doc.mjs` is a reader and a validator; it is never a renderer, so D-01's "Markdown-only, no JSON intermediate" decision stands untouched.

Output: a fixture target repo, `scripts/discover-schema.mjs`, `scripts/test-case-doc.mjs`, `references/test-case-format.md`, a golden conforming document, an end-to-end test, and the two new `SKILL.md` protocol sections that make the whole thing runnable by a developer who has read nothing else.

Implements D-01 (output path and naming), D-02 (exactly the five DISC-02 fields), D-03 (explicit `Ejecución: API | UI` set at discovery time), D-04 (document-scoped `case-N` IDs), D-05 (one section per discovered surface), D-09 (Supabase migration constraints inform the negativo/edge labeling) and D-10 (generation is a terminal step for the invocation).
</objective>
