<objective>
**As a** developer whose projects mix API routes, Server-Action forms and plain fetch-backed forms, **I want to** have the QA agent find all of those surfaces on its own, whichever router layout the project uses, **so that** I get test cases for the forms my users actually touch and not only for the endpoints I happened to remember.

Plan 03-01 proved the chain end to end on a single API surface. This plan widens the discovery half of that chain to everything DISC-01 names — forms, Server Actions, imperative validation, and both Next.js router layouts — leaving the generation half and the document contract exactly as 03-01 wrote them.

Purpose: RESEARCH read all three target repos directly this session and found that the variation D-08 anticipated is not where the risk actually is. All three repos are App Router only, so router detection is the *defensive* branch. The real cross-repo variation is how a form submits: franquix's five auth forms bind to a colocated `'use server'` action, while dotax and DATAX-web use client components that `fetch()` an API route. A discovery pass that assumes one mechanism silently mislabels five real surfaces in one of the three repos we test against. That is what this plan's fixtures and detection rules exist to prevent.

Output: four new fixture surfaces in the App Router mock repo, two small fixture repos covering the Pages Router and hybrid layouts, `references/discovery-nextjs.md` as the detection-rule contract, an automated proof that each documented pattern finds what it claims, and the expanded `## Discovery protocol` in `SKILL.md`.

Implements D-07 (full-project scan is the default, with build output excluded), D-08 (automatic router-layout detection with no user flag) and the app-level half of D-09 (validation colocated with route handlers informs how a case is labeled).
</objective>
