<objective>
**As a** developer who just changed a form in one of our apps, **I want to** say `probá el alta de cliente` and have the agent actually walk that flow in a browser and hand me a report with what it saw at each step, **so that** I stop re-running the same click-through by hand after every change.

This is the slice that turns the phase's proven authentication path into the capability the phase exists for. Plan 02-01 proved a session can be obtained and shared; plan 02-02 put the confirmation gate in place before any click was possible; plan 02-03 registered the browser-control server. This plan wires the natural-language instruction to real browser actions and makes their results first-class citizens of the report Phase 1 already produces.

Purpose: the project's foundational rule is that the model never narrates a verdict. Phase 1 enforced that by making `api-client.mjs` the only source of pass and fail, with `format-report.mjs` refusing to render a verdict that has no evidence behind it. A browser step has no HTTP response to serve as that evidence, so this plan supplies the equivalent — an accessibility snapshot captured at the moment of the action, written to disk, and required before a UI verdict may be recorded. Without it, UI testing would be exactly the hallucinated-success failure mode the project's own research names as its first pitfall.

Output: a UI case recorder, a report renderer that handles browser evidence, and the run protocol in `SKILL.md` that ties instruction, snapshot, gate, action, re-snapshot and record into one loop.

Implements D-01 (Playwright MCP drives the flow), D-02 (one Chromium context), D-03 (role and accessible name, never CSS selectors), D-05 and D-06 (the gate from plan 02-02 sits inside this loop), and D-07 (API calls after the flow reuse the same session).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| natural-language instruction → executed browser actions | The developer's sentence is interpreted by the model and becomes real mutations in a real environment |

| orchestrator observation → recorded verdict | The point at which a model could assert a pass it did not observe |
| snapshot files on disk → the report a developer may share | Captured page content can include real data from the target environment |
