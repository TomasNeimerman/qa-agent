<objective>
Turn the tracer's minimal report into the deliverable ROADMAP success criterion 4 actually asks for: a readable report that says what was tested and what passed or failed, where every verdict quotes the evidence that produced it, every failure carries reproduction steps, and actions blocked pending confirmation are visibly separated from actions that really ran.

Purpose: the project's own PITFALLS.md names hallucinated success as pitfall 1 — an agent that reports a pass it never observed. The countermeasure is structural, not exhortative: the formatter reads `results.json` and nothing else, and it refuses to emit a verdict whose evidence is missing. This plan makes that refusal real and gives the output a shape a developer will actually read.

Output: the canonical report template, a renderer that implements it exactly, and unit coverage for all three case states.

Implements D-04 (declined cases surfaced as blocked, run continues), D-07 (chat summary plus a Markdown file under the target project's `qa-reports/`), D-08 (full request and full response rendered for passing and failing cases alike), D-10 (shape checks labelled as observed rather than contract-validated).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| results.json → Markdown report | Structured evidence crosses into a human-readable artifact that a developer will trust and may share |
| report renderer → target repo filesystem | The renderer writes into a repository it does not own |
| response bodies → report file | Target-app response payloads, possibly containing test-user data, are persisted to disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Repudiation | `renderReport` verdict rows | high | mitigate | `EvidenceMissingError` is thrown for any `passed` or `failed` case lacking `evidence.response`, so an unevidenced verdict aborts the whole report rather than being quietly rendered (SAFE-03) |
| T-01-12 | Tampering | reproduction steps | medium | mitigate | `deriveReproSteps` composes every string from `evidence.request`, `checks` and `run.baseUrl`; no narrative or model-authored field is a source, making a fabricated repro step structurally impossible |
| T-01-13 | Information Disclosure | reproduction steps and curl line | high | mitigate | The steps reference the credential only as `$QA_AGENT_TOKEN`; a unit test asserts the fixture token value appears nowhere in the derived steps, and headers are rendered from the already-redacted stored copy |
| T-01-14 | Information Disclosure | response bodies persisted under `qa-reports/` | medium | accept | Reports are local-only artifacts of a test environment, written into a directory the formatter gitignores on creation; excluding response bodies would break D-08 and SAFE-03, which are the phase's core requirements |
| T-01-15 | Denial of Service | oversized chat summary from a large run | low | mitigate | `chatSummary` caps failed and blocked listings at five entries each with a remainder count, keeping the chat delivery bounded regardless of case count |
</threat_model>
